apiVersion: v1
kind: Service
metadata:
  name: my-service
spec:
  type: NodePort
  selector:
    app: python-app
  ports:
    - port: 80  ## this is service's port
      # By default and for convenience, the `targetPort` is set to
      # the same value as the `port` field.
      targetPort: 80  ## container's port
      # Optional field
      # By default and for convenience, the Kubernetes control plane
      # will allocate a port from a range (default: 30000-32767)
      nodePort: 30007  ## Exposed port on each Node (Main entry)


1. 🏙️ nodePort = Gate of the building (Main Entrance)
This is the only place outsiders (like the delivery guy or you from the internet) can enter.

It's public-facing and the first point of contact.

You can think of this as port 30007 on the Node.

So the delivery guy enters the gate using address: NodeIP:30007

2. 🛎️ port = Reception desk inside the building
Once the delivery guy gets in through the gate, he meets the reception.

The reception (Service port: 80) decides which apartment to forward the request to.

The receptionist knows all the apartments (pods) and how to reach them.

3. 🚪 targetPort = Actual apartment door number
This is where your friend lives — the actual destination.

It’s the port where the app inside the pod is running — like port 80 on the container.

The receptionist forwards the delivery to apartment 80.

apiVersion: v1
kind: Service
metadata:
  name: my-service
spec:
  type: NodePort
  selector:
    app.kubernetes.io/name: MyApp
  ports:
    - port: 80   ## Service port
      # By default and for convenience, the `targetPort` is set to
      # the same value as the `port` field.
      targetPort: 80  ## Container port
      # Optional field
      # By default and for convenience, the Kubernetes control plane
      # will allocate a port from a range (default: 30000-32767)
      nodePort: 30007 ## Exposed port on each Node (Main entry)




# port: 80: This is the port the service will expose within the cluster (for internal traffic). Other services or Pods within the cluster can reach this service by using port 80.

# targetPort: 8000: This is the port where your application is running inside the "container". The traffic is routed to this port inside the Pods that are selected by the service.

# nodePort: 30007: This is the port exposed on each node in the cluster, which will allow external traffic to access the application. In this case, the application is accessible at any node's IP address on port 30007.
